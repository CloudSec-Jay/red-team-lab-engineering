# API security labs

The archived repository named REST, GraphQL, OAuth, JWT, API-key abuse, object authorization, mass assignment, rate limiting, introspection, and batching as intended coverage. Its API implementation folders and notes were empty.

This track therefore begins as scaffolding:

- Object-level authorization using two test identities and synthetic records.
- Token acceptance boundaries covering issuer, audience, expiry, and algorithm policy.
- Schema and operation exposure for a local GraphQL service.
- Rate-limit behavior using bounded, low-volume test cases.
- Property authorization for create and update operations.

No API test is considered implemented until a local target definition, telemetry plan, teardown procedure, and evidence manifest exist.
